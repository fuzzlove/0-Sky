# Repository audit and release-readiness report

## Scope and preservation

The audit began from revision `30d2bdc15a906d3d081f6ce64e5f6b9012e511da`
with seven local commits, one remote README commit, tracked edits, and relevant
untracked compatibility sources/tests. The original working tree was not
modified. A recoverable checkpoint was created below `.git/codex-checkpoints/`
before cleanup, and the active work was committed separately on the dedicated
cleanup branch before audit changes.

The complete current file classification is generated by
`tools/repository_inventory.py` into
`manifests/repository-inventory.json`. The generator hashes every tracked or
pending non-ignored file and uses these categories:

| Category | Treatment |
| --- | --- |
| Required source or maintenance tests | Retained. Tests are maintenance inputs, not distribution payloads. |
| Required installation or runtime assets | Retained and admitted only through existing build/kit manifests. |
| Reproducible build output | Excluded by `.gitignore` and the release allowlist. |
| Verified obsolete or temporary artifacts | Removed only after duplicate/reference/history checks. |
| Uncertain files requiring investigation | Retained, identified in the inventory, and excluded from the binary package. Most are historical `addons/PoC` research paths. |

## Findings and implemented fixes

### High severity / release blockers

1. **Signed external payloads contain builder paths.** The existing sanitizer
   correctly blocks them. They cannot be safely edited without invalidating
   signatures. **Status:** open blocker; rebuild from corrected source/build
   settings, re-sign, and re-run the release gate.
2. **Distribution signing, notarization, clean Intel runtime testing, and the
   exact supported SRD matrix require external credentials/hardware.**
   **Status:** accurately reported as unavailable, never promoted to PASS.

No credential value was printed or copied. The tracked-source PII gate found
no unallowlisted credential, private key, fixed home path, or physical device
identifier.

### Medium severity

1. **Release output could accumulate a stale package or unrelated file.** The
   release builder now rejects non-empty output (apart from a prior failure
   report), and the final directory is an explicit four-file allowlist.
2. **Release artifacts lacked a detached machine-verifiable manifest.** The
   builder now emits `RELEASE_MANIFEST.json` and `SHA256SUMS`; verification
   rejects extra files, symlinks, unsafe names, duplicate entries, size/hash
   drift, and an unexpected package name.
3. **Independent verification depended on a retained staged app.**
   `verify_release.py` can now expand and verify the package directly and can
   bind the selected package to its release-directory manifest.
4. **Several host setup probes had no timeout.** Python, Xcode, LaunchAgent,
   pairing-proof, Command Line Tools, and device-picker subprocesses now have
   bounded waits and actionable failure results.
5. **Installation and release instructions were fragmented.** `INSTALL.md` is
   now the user entry point; source building and release engineering remain
   separate. Repair, upgrade, reversible uninstall, privilege requests, and
   exact-device selection are documented.

### Low severity

1. Removed `combined_requirements.txt`: an unreferenced near-duplicate of the
   canonical pinned requirements used by reproducibility restore.
2. Removed `tools/patches/doodle-ios27-source-probe-v1.patch`: byte-identical to
   the referenced canonical patch and itself unreferenced.
3. Added ignore rules for test caches, coverage, crash dumps, editor remnants,
   Xcode result bundles, and the locally assembled `addons/PoC/yoridan/`
   delivery tree.

## Retained uncertain or duplicate files

- `addons/PoC/transport_stage.py` duplicates the tracked host transport module,
  but may be a standalone field-recovery entry point; it was retained.
- Root `setup_0sky_devices.*` wrappers have no in-repository callers, but are
  retained as public compatibility entry points. All delegate to
  `bridge/macos_host_setup.py`; no duplicate installer logic remains there.
- Historical release notes, reproducibility patches, vendored SRD shell source,
  and compatibility evidence were retained because absence of textual callers
  does not prove they are disposable.
- Local ignored builds, device exports, logs, and tester deliveries were not
  copied to the cleanup worktree or public package. The user confirmed that the
  previously inventoried `addons/PoC/yoridan/` delivery tree was removed; its
  checkpoint inventory is metadata only, not a content backup. These local
  outputs remain outside the release allowlist.

## Security and correctness review

- Core install/release subprocesses use argument arrays, explicit timeouts, and
  checked return codes; no new shell interpolation was introduced.
- Archive/package verification confines paths, rejects unsafe symlinks and
  unexpected payload roots, and compares the expanded package to the audited
  app when both are available.
- Installer profiles require an exact UDID, validate device/endpoint ownership,
  keep secrets in owner-only state, and refuse another device's configuration.
- Host uninstall is dry-run by default, exact-device scoped, rollback-backed,
  and does not alter Apple pairing or the SRD.
- Intel and Apple-silicon slices and wheel coverage are statically verified;
  runtime claims remain limited to actually exercised hardware.

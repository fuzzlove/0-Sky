# Installation and release troubleshooting

Run diagnostics before making changes:

```sh
python3 tools/environment_preflight.py --human --mode development \
  --kit "/absolute/path/to/authorized kit" \
  --theos "/absolute/path/to/locked/theos" --skip-device
python3 tools/pii_audit.py .
```

Add `--udid EXACT_UDID` only when the intended SRD is connected and unlocked.
Preflight is read-only; setup and repair are explicit operations.

| Symptom | Meaning | Action |
| --- | --- | --- |
| Doctor reports `xcrun` or `xcodebuild` missing/incompatible | Full Xcode is absent, unfinished, or not selected. | Install Xcode from the Mac App Store, open it once, then run `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, `sudo xcodebuild -license accept`, and `xcodebuild -version`. |
| Doctor reports Python missing | A source-build interpreter is not on `PATH`; this does not mean binary-release users need Python. | Install the universal2 macOS package from <https://www.python.org/downloads/macos/> or run `brew install python@3.12`; open a new Terminal and run `python3 --version`. |
| Doctor reports locked Theos missing | The required clean checkout and recursive submodules were not selected. | Run the three exact clone/checkout/submodule commands printed by `--human`, then rerun with `--theos '/absolute/path/to/theos'`. |
| Doctor reports a Developer ID identity missing | The matching distribution certificate or private key is absent from the unlocked login keychain. | In the Apple Developer certificate portal create the reported **Developer ID Application** or **Developer ID Installer** certificate, upload the CSR matching this Mac's private key, download the `.cer`, and open it in Keychain Access. Verify both with `security find-identity -v -p basic`. |
| Doctor reports a notarytool profile missing | Developer ID signing is available, but Apple notarization credentials have not been stored. | Create an app-specific password at <https://account.apple.com>, run `xcrun notarytool store-credentials 0-sky-release --apple-id YOUR_APPLE_ID --team-id YOUR_TEAM_ID`, type the app-specific password only at the secure prompt, and rerun preflight with `--notary-profile 0-sky-release`. |
| `LIBARCHIVE_NOT_RESOLVED` or `OPENSSL_NOT_RESOLVED` | The Control source-build headers are absent or `pkg-config` cannot find them. | Run `brew install libarchive openssl@3 pkgconf ldid dpkg`, then export `LIBARCHIVE_PREFIX="$(brew --prefix libarchive)"` and `PKG_CONFIG_PATH="$(brew --prefix openssl@3)/lib/pkgconfig${PKG_CONFIG_PATH:+:$PKG_CONFIG_PATH}"` in the same Terminal. |
| `EXTERNAL_KIT_MISSING` | A source checkout lacks the separately supplied, manifest-verified kit. | Run `Install 0-Sky Dependencies.command`; it opens a folder chooser. Select the directory that **directly** contains `SHA256SUMS`, `host-mac`, `payloads`, and `host-mac/wheelhouse`. For a headless run use `Install 0-Sky Dependencies.command --kit '/absolute/path/to/verified kit'`. A signed downloaded app must use its embedded `Contents/Resources/Kit`; reinstall a complete package instead of bypassing that boundary. |
| `Required dependency is missing: complete 0-Sky kit in this app bundle` after a package install | The package is absent/incomplete, or its root-owned embedded kit is not readable by the logged-in user. Experimental `v1.0.0-pre.10` had this packaging-mode defect. | Remove that app and install the complete replacement experimental release. Do not use `sudo chmod`, copy a kit from another Mac, or bypass signature verification. The replacement release gate rejects kit directories without world read/traverse access and data files without world read access. |
| `ENVIRONMENT_BLOCKED` or missing Python 3.12 | Required host tools or the pinned runtime are unavailable. | In Bridge choose **Install All 0-Sky Requirements**, then rerun preflight. |
| `HOST_RUNTIME=FAIL` | The package lacks a required Universal 2 Python/tool binary, license, or matching hash. | Replace the complete four-file release; do not install Homebrew as a substitute for a broken public package. |
| `BLOCKED_HOST_RUNTIME_MISSING_OR_INVALID` | A source release build was given a kit without the manifest-verified Universal 2 host runtime. | Supply/rebuild the authorized runtime kit; the release command will not fall back to developer-installed tools. |
| `THEOS_PREFLIGHT=FAIL` | The Theos checkout, a recursive submodule, SDK, or source-build dependency differs from the lock. | Initialize the commit in `manifests/source-dependencies.json` recursively and pass it with `--theos`; do not update it during a release build. |
| More than one USB device is visible | Automatic selection would be ambiguous. | Disconnect other devices or explicitly select/pass the exact UDID. |
| Trust or pairing fails | Apple trust, project pairing, SSH, and worker state are separate checks. | Unlock the selected SRD, approve Trust, verify Xcode device support, and rerun the exact-device check. Do not copy another device's profile. |
| SSH port is occupied | The requested local port belongs to another listener. | Stop the verified stale per-device forward or choose another local port. Never terminate an unidentified listener. |
| Existing profile belongs to another endpoint | Stored UDID, instance, SSH key, port, or manifest revision differs. | Use the audited repair path or a new instance name; do not edit `config.json` by hand. |
| `ERR_PROFILE_STALE: Multiple profiles claim this UUID` during setup | An interrupted or older setup directory has the selected device UUID. Earlier experimental builds counted incomplete directories as complete profiles and could choose one by filesystem order. | Install `v1.0.0-pre.12` or later and press **Resume**/**Set Up New Device** with that exact unlocked SRD connected by USB. Bridge validates every candidate, resumes the deterministic exact-device directory, reserves ports used by incomplete profiles, and uses a sole complete profile without deleting the incomplete copies. If two *complete* profiles exist it reports `ERR_PROFILE_CONFLICT` and refuses to choose silently; export Diagnostics before removing only the obsolete Mac-side enrollment. Do not edit `config.json`, copy pairing records, or delete device data. |
| `INSTALL=FAIL REASON=existing Apple and 0-Sky pairing exited 2` | The pairing child reported a specific trust, USB, identity, SSH, or timeout failure. Pre.11 discarded that child stderr and incorrectly referred users to a log it had not written. | Install pre.12 or later and press **Resume** with the same unlocked SRD connected directly by USB. The UI now includes a redacted cause and exact recovery action. Full output is stored owner-only at `~/Library/Application Support/0-Sky/instances/<instance>/logs/pairing-last.log`; do not publish it because it can contain device identifiers and host fingerprints. Use **Export Diagnostics** for a redacted report. |
| A fresh SRD reports pairing exit `2`, SSH connection refused, and later Control health failure | Host-only pairing was started before the fresh device had SRDssh/Procursus. The Control error is downstream, not the root cause. | Install pre.13 or later, select the exact USB SRD, choose **Set Up New Device…**, and confirm **Enroll New Device and Install Complete Project…**. This uses exact-device RemoteXPC to prepare SRDssh before host pairing. Keep the SRD unlocked and do not manually edit or delete the incomplete profile; setup resumes it. |
| Complete Project `--check` reports `kit integrity check failed` for a relative Python entry point such as `2to3` | Pre.12's controller allowed only one SRD applet symlink and incorrectly rejected safe manifest-bound links in the Universal Python runtime. | Install pre.13 or later. Do not replace the runtime file or bypass the integrity gate. The corrected gate accepts only relative links resolving inside the signed kit and still checks target bytes against `SHA256SUMS`. |
| Fresh-SRD setup reports `Compatibility UNKNOWN: srdssh/bootstrap.py has no transactional service adapter` or rejects `srdsh-authorized-key.pub` | Pre.12 release preparation replaced the reviewed SRDssh bootstrap with a blocking placeholder; an older source checksum also did not match the manifest-bound public key. | Install pre.13 or later. Keep the exact SRD selected and unlocked, then choose **Resume**. Pre.13 ships the reviewed adapter, verifies all SRDssh files, checks native and USB RemoteXPC, obtains an exact-device domain-3 nonce and Apple ticket, and only then offers the device-changing stage. Do not bypass the manifest or copy another device's pairing material. |
| `Invalid or unapproved path` names `python3` after upgrading on Intel or Apple silicon | A previous 0-Sky environment is healthy but its interpreter resolves to Homebrew or another developer-local installation outside the signed application. Pre.13 showed it as available, then the execution allowlist correctly blocked it. | Install pre.14 or later. Open **Dependencies**, click **Install All 0-Sky Requirements**, and wait for `REQUIREMENTS=PASS`; then select the same SRD and choose **Resume**. The offline repair uses bundled Python, needs no Homebrew, preserves the old environment under `~/Library/Application Support/0-Sky/recovery/`, and restores it automatically if rebuilding fails. Do not add `/usr/local` or Homebrew to the app's execution allowlist. |
| Requirements repair reports a Frida wheel digest mismatch | A signed pre.13 package updated native code inside the wheel but retained its pre-signing nested checksum. | Install pre.14 or later and run **Install All 0-Sky Requirements** again. The release signer now regenerates the path-confined Frida checksum manifest after signing and before the outer kit manifest is sealed. |
| `install failed: instance uses another kit revision` | The exact-device profile was staged by an older verified app. Pre.14 correctly refused to mix revisions but referred to a refresh path that did not update host-staged assets. | Install pre.15 or later, select the same unlocked SRD over USB, and press **Resume**. The app validates endpoint ownership, privately checkpoints the old staged kit, atomically installs the current assets, preserves pairing/keys/logs/Python, and rolls back on failure. Do not delete `~/Library/Application Support/0-Sky`, edit `config.json`, or reuse another device's profile. Expand the technical log and look for `KIT_REFRESH=PASS`; the reported checkpoint is owner-only recovery evidence. |
| `existing profile ssh_port belongs to another endpoint` after a successful `KIT_REFRESH=PASS` | Pre.15's Python controller saw the prior exact-device tunnel listening on the saved port, allocated the next port, and then correctly failed the endpoint-integrity check. | Install pre.16 or later and press **Resume** with the same unlocked SRD connected over USB. Resume validates and reuses the saved exact-device port even while its tunnel is listening; ports owned by other profiles remain reserved. Do not edit the port in `config.json` or terminate unrelated listeners manually. |
| iOS 27 fails at `RemoteXPC handshake` / `PreferredRsdTunnel ... timed out` after reusing the saved USB tunnel | The selected iOS 27 SRD has not yet completed its device-initiated Paired Macs relationship. Pre.16's packaged GUI did not enable the controller's supported fallback, so rerunning repeated the same timeout. | Install pre.17 or later and press **Resume**. When instructed, unlock the SRD and open **Settings → Developer → Paired Macs**, select this Mac, and complete the displayed code flow within three minutes. Setup then retries and verifies the exact selected UDID. Do not copy another device's pairing records or disable trust checks. |
| Setup times out | A child tool, pairing proof, or device-selection dialog did not complete. | Confirm the device is unlocked and the required tool is responsive, then rerun. Timeouts fail closed and do not prove installation. |
| `OUTPUT_NOT_EMPTY` | A release output directory contains stale or unrecognized artifacts. | Choose a new empty output directory. Keep previous releases immutable. |
| `RELEASE_MANIFEST=FAIL` | A release file is missing, extra, symlinked, or has changed bytes. | Re-download/rebuild the complete four-file set. Do not replace only the package. |
| Candidate audit ends `BLOCKED` | Development/release-candidate signing is not a public distribution result. | Use a distribution build with verified Developer ID signatures and notarization. |
| Sanitization reports a signed binary path as an advisory | An upstream binary or test fixture retains a source/debug string; an arbitrary string alone does not prove a runtime dependency or secret. | Review the advisory report. The verifier separately inspects Mach-O load commands and fails on an actual nonportable dependency/RPATH. Exact public test fixtures are accepted only when archive SHA-256, member prefix, and category match `manifests/release-sanitizer-exceptions.json`. Never add a broad exception. |
| `NONPORTABLE_MACHO_RUNTIME_PATH` | A native executable actually loads from a developer, temporary, Homebrew, MacPorts, or mounted-volume path. | Correct the canonical linker/RPATH configuration, rebuild, and re-sign. Do not patch a signed binary in place. |
| `OFFLINE_WHEEL_ARCHITECTURE_COVERAGE_FAILED` | The selected kit is missing a locked arm64/x86_64 wheel pair. | Run `python3 tools/wheel_inventory.py '/absolute/path/to/kit'`; replace every reported missing/single-architecture wheel, then rerun the build. |
| Control reports “Verified update required” | A moving upstream `latest` asset has no release-bound checksum. | Upgrade using a complete manifest-verified 0-Sky release instead of the disabled privileged self-updater. |

## Private logs and state

0-Sky state belongs below `~/Library/Application Support/0-Sky`; normal logs
belong below `~/Library/Logs/0-Sky`. Do not attach unredacted logs, pairing
records, keys, device identifiers, or configuration files to public issues.
Use Bridge's redacted diagnostic export where available.

## Recovery boundaries

- A failed build does not prove an installed app is valid.
- A successful SSH command does not prove Apple pairing or worker identity.
- A matching architecture slice does not prove Intel or Apple-silicon runtime
  behavior; record unavailable hardware tests as `NOT_EXECUTED`.
- Host uninstall does not uninstall device payloads. Device removal or restore
  requires its separately documented, exact-device workflow.
